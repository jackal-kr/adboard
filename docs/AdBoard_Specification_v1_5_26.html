01Purpose & Scope

Ad Board (com_adboard) is a moderated classifieds component for Joomla 6.1, built for the S.O.D. Dojazdów garden plot association. It allows any site visitor to post an advertisement (plot for sale, plant exchange, tools, services) without a Joomla account. All submissions enter a moderation queue and are published only after an administrator or moderator approves them.

Design Goals

  • Zero-account submission — public visitors submit via a standard HTML form, no login required.
  • Moderation-first — no ad is visible publicly until explicitly approved.
  • Multi-layer security — honeypot, IP rate limiting, CAPTCHA, GD image re-encode, CSRF tokens.
  • Joomla-native — uses Joomla ACL, action logs, Smart Search, and the Web Asset Manager.
  • Minimal footprint — single component + one optional finder plugin, no external dependencies.

Out of Scope (Planned Backlog)

  • Self-service ad management via secret token (edit / withdraw after submission).
  • Email notification to submitter on approval or rejection.
  • GDPR consent checkbox on the submission form.
  • SEF URL router (router.php).
  • "Mark as sold / resolved" state (state = 3).
  • Plot number field (garden-association-specific metadata).

Ad States

Lazy expiry flip: There is no cron job. When AdsModel::getListQuery() executes on the admin list page, it runs a single UPDATE to flip state 1 → 2 for all ads where publish_down < NOW(). This keeps the schema simple while ensuring expired ads are never shown publicly.

05Functional Specification

5.1 Public Submission Form

5.2 Public Listing Page

  • Displays all ads with state = 1 (Published) and publish_down > NOW().
  • Filter row: category drop-down + free-text search (title / description).
  • Sort controls: Newest, Oldest, Title A–Z; configurable items-per-page.
  • Each card shows: cover image, title, category badge, expiry date, hit count.
  • All filter/sort changes update the URL (Itemid-aware) so the sidebar module remains active.

5.3 Public Detail Page

  • Full ad view: all images in a scrollable gallery, title, category, description, contact, dates.
  • Lightbox: clicking any image opens a fullscreen overlay with previous/next navigation.
  • Keyboard: arrow keys navigate; Escape or × closes. Touch: swipe gestures supported.
  • Hit counter incremented on each page load.

5.4 Admin Ad List

  • Paginated table of all ads with state badge, title, category, submitter IP, dates, hit count.
  • Pending count badge in the toolbar header when state-0 ads exist.
  • Inline "View on site" icon on published ads.
  • Bulk actions: Approve (publish), Unpublish, Reject, Delete.
  • Guard on bulk Approve: ads with publish_down in the past are skipped with a warning.

5.5 Admin Ad Edit

  • Fields: Title, Category, Description, Contact, Images (drag-to-reorder), Expiry date, State.
  • Sidebar: Status, Publish Up / Publish Down date pickers, Hits (read-only), IP address (read-only).
  • Saving a Pending or Rejected ad to state=Published sets publish_up = NOW() if not already set.

5.6 Action Logging

Every admin action writes an entry to the Joomla action log (#__action_logs) via the Joomla 6.1 MVC API (bootComponent / createModel). Entries appear in the Home Dashboard → Latest Actions panel and at ?option=com_actionlogs.

ActionLog message format
Approve / publish (bulk)Ad Board: {username} approved / published {count} ad(s) (IDs: {ids}).
Unpublish (bulk)Ad Board: {username} unpublished {count} ad(s) (IDs: {ids}).
Reject (bulk)Ad Board: {username} rejected {count} ad(s) (IDs: {ids}).
Delete (bulk)Ad Board: {username} deleted {count} ad(s) (IDs: {ids}).
Save / update (individual)Ad Board: {username} updated ad "{title}" (ID {id}).
Create (individual)Ad Board: {username} created ad "{title}" (ID {id}).

The username in each entry is a clickable hyperlink to the Joomla user edit page. Logging is non-fatal — a failure does not interrupt the admin action.

5.6.1 Change Detection for Save / Update

Save and update events are only written to the log when the ad data actually changed. Opening an ad and clicking Save & Close without modifying anything produces no log entry. The mechanism:

  1. getAdSnapshot(int $id) reads 7 editable fields from the DB before saving and returns md5(serialize($row)).
  2. After saveRecord() completes, a second snapshot is taken.
  3. If the hashes differ — or it is a new record — the log entry is written. Identical hashes → no log entry.

Fields included in the snapshot: title, category, description, contact, state, publish_up, publish_down. Image changes are not included (images are processed separately after the main save).

5.7 Email Notification

  • Triggered on public form submission when email_notify param = 1 (default: On).
  • Sent to the address in Joomla Global Configuration → Server → From Email.
  • Email content sanitised via TextHelper::sanitize() before embedding.
  • Toggle in Options → General → Notifications section (Yes / No radio).

5.8 Smart Search Integration

  • Provided by plg_finder_adboard (finder/adboard) v1.5.2.
  • Indexes: title, category, description, contact of all state=1, non-expired ads.
  • onFinderGarbageCollection removes expired and unpublished ads from the index automatically.
  • Content type "Advertisements" appears in the Smart Search type filter.
  • Search result links use the SEF URL (/ogloszenia/12) — the plugin resolves the site menu item Itemid at index time and stores it in the route field. The url field (used for GC deduplication) intentionally does not contain an Itemid.
  • Re-index required after any component upgrade to refresh stored route URLs.

5.9 SEF URL Structure

With Joomla SEF URLs enabled (Global Configuration → SEO Settings), the router produces clean URLs automatically for all Route::_() calls in the templates:

ViewInternal URLSEF URL
Listing?view=ads/ogloszenia  (menu item root, no segment added)
Single ad?view=ad&id=12/ogloszenia/12
Submit form?view=form/ogloszenia/dodaj
No slug column required. The auto-increment id uniquely identifies each ad. Using a slug would require an extra DB column, a migration, and title-change handling — with no practical benefit for short-lived classifieds ads.

8.2 Image Upload Security Pipeline

ImageHelper applies the following checks in strict order, rejecting on first failure:

  1. is_uploaded_file() — confirms the file arrived via HTTP upload; rejects path injection.
  2. File size check against max_image_size param (uses PHP's $_FILES['size'], not user-supplied).
  3. finfo(FILEINFO_MIME_TYPE) reads actual file bytes — ignores the file extension entirely.
  4. MIME type must be one of: image/jpeg, image/png, image/gif, image/webp.
  5. File extension must match the detected MIME type (cross-check against allow-list map).
  6. getimagesize() reads image headers only to check width × height ≤ 12,000,000 px (12 MP). Prevents OOM attacks without loading the full image into RAM.
  7. GD imagecreatefrom*() fully decodes the image. Corrupt or polyglot files fail here. EXIF metadata and embedded payloads are stripped.
  8. Image resized to fit within 1920 × 1920 px bounding box; re-saved as a clean file.
  9. Output filename is bin2hex(random_bytes(12)) — no user input in the filesystem path.
Defence in depth: PHP's own upload_max_filesize and post_max_size ini settings cap uploads at the server level before any component code runs, providing an additional first barrier.

8.3 Submission Anti-Spam

MechanismHow it works
Honeypot fieldA hidden input with a name bots typically fill. Non-empty value silently discards the submission without revealing the rejection.
IP rate limitingCounts state=0 records with matching ip_address created within the configured window. Rejects with an error message if limit exceeded.
CAPTCHARendered when a CAPTCHA plugin is configured in Joomla Global Configuration. Validated server-side in FormController. Joomla 6.1 built-in "I'm not a robot" checkbox is supported.
Admin moderationEvery submission enters state=0 regardless of other checks. Nothing is visible publicly until explicitly approved by a moderator.

8.4 Path Traversal Protection

The keep_images[] POST array (used when editing an ad to specify which existing images to retain) is filtered through ImageHelper::filterKeepList(), which applies basename() and validates against the strict regex /^[a-f0-9]{24}\.[a-z]{3,4}$/ — matching only the random hex filenames generated by the component itself.

10Smart Search Finder Plugin

plg_finder_adboard (finder/adboard) is a standalone Joomla Smart Search adapter that indexes Ad Board advertisements for full-text site search.

PropertyValue
Extension typePlugin — group: finder

Key Method Overrides

MethodPurpose
getListQuery()Returns only published, non-expired ads for indexing
index()Sets $item->url (GC deduplication key, no Itemid) and $item->route (search result link, includes Itemid for SEF URL production)
getAdboardItemid()Queries #__menu once per indexing run (statically cached) to find the first published site menu item for com_adboard
onFinderGarbageCollection()Removes expired and unpublished ads from the search index during scheduled maintenance
url vs route: $item->url is stored without Itemid so garbage collection LIKE matching works regardless of menu changes. $item->route includes &Itemid=X so Route::_() produces /ogloszenia/12 in search results. A re-index is required after menu restructuring.

Setup Procedure

  1. Install the full package (plugin is included automatically).
  2. Go to System → Plugins, filter by Type = finder, enable Smart Search – Ad Board.
  3. Go to Components → Smart Search, click Index in the toolbar.
  4. Wait for the progress bar to complete. Ads now appear in site search results.
Database note: The plugin uses $this->db ?? Factory::getDbo() to get the database driver, not getDatabase() which is unavailable in the old-style Adapter base class.

Fresh Install

  1. Download pkg_adboard_v{version}.zip.
  2. System → Install → Extensions → Upload Package File.
  3. Joomla creates #__adboard, seeds default categories and expiry terms, sets Manager group permissions, and registers the action log config.
  4. Enable the Smart Search – Ad Board plugin (System → Plugins).
  5. Run a full Smart Search index (Components → Smart Search → Index).
  6. Create a site menu item: Menus → [menu] → New → Ad Board → Listing or Submission Form.

Upgrade

  1. Install the new package ZIP on top of the existing installation (method="upgrade" in manifest).
  2. Joomla automatically runs any pending SQL migration scripts from admin/sql/updates/mysql/ based on the stored schema version.
  3. No data loss — the upgrade path only adds or removes columns; never truncates.
